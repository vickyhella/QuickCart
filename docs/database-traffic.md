# 数据库流量维护

Neon 的 Network transfer 是数据库传给应用的数据，不等于网站图片下载量，也不能用 Rows 图里的新增 / 修改条数换算。公开 feed 的平台抓取、开发调试、后台操作、网站爬虫都可能读取数据库；没有顾客访问并不代表没有请求。

## 已实现的保护

- `lib/storefront-catalog.ts`：商品列表、商品名称搜索、商品页 SEO、首页和 Merchant / Pinterest 的 XML / 预览共用一份公开商品目录。只查已发布商品及所需字段；每批最多 100 件，并遍历所有页，避免目录超过 100 件后遗漏。媒体 ID 集中查询，只读取 URL、替代文字和文件名，不展开商品供应商或图片原图关系。
- `lib/storefront-cache.ts`：目录、首页设置、导航及内容页面在服务端缓存 300 秒。缓存过期后由下一次访问触发刷新，没有定时轮询；同一实例同时首次读取目录时合并请求。读库失败不会伪装成空目录写入缓存。
- 首页独立组合目录、设置与图片缓存，避免嵌套 `unstable_cache` 时 Next 跳过内部缓存而重新读库。
- Products / Pages / Media hooks 和 Marketing settings / Product dimensions hooks：通过 `revalidateTag(tag, { expire: 0 })` 清除相关缓存，让保存后的下一次请求取新内容。草稿编辑不会反复清除公开目录缓存；商品发布、下架及已发布商品的库存修改会清除缓存。
- 浏览器响应仍使用 `no-store`，这里关闭的是浏览器 / CDN 的第二层缓存，不是上面的 Next 服务端数据缓存。这样无需等 CDN 到期才能看到后台修改。已打开页面需刷新或重新加载数据。
- CLI 脚本不处于 Next 请求中，无法执行即时失效；由最多 5 分钟的缓存有效期兜底。
- Marketing 图片 / 商品选择器、Product Studio 列表、Categories 和图片压缩候选列表只读取实际使用的字段。Spreadsheet 首次加载媒体 / 供应商选项，翻页只加载商品；上传图片仍立即补入当前选项。
- Product Studio / Products 的图片巡检由 `Check product images` 按钮触发，避免每次打开列表都全库扫描和检查图片文件。
- 商品编号仅查询 SKU；商品供应商关联不变时不重复统计。修改商品标题 / 描述模板仍会刷新自动生成内容，但同一请求只读取一次配置，并把刚保存的模板传给后续商品更新。手写内容不受影响。
- 公共图片权限仅查询图片引用，并在同一请求内复用结果；公开范围包含已发布商品、首页主图 / Mystery Box 和分类预览图，仍不开放无引用的草稿图或 Media Originals。

## 部署与确认

本次不涉及 schema、migration、新依赖或新环境变量。正常提交并部署应用即可；代码优化不会解除已经触发的 Neon 月度额度暂停。

1. 项目恢复后确认最新代码已部署。打开首页、搜索商品、访问商品页，再打开两个 feed，检查图片、商品链接和内容正常。
2. 在后台修改首页图片后保存，刷新首页；发布 / 下架商品及修改价格、库存后，重新请求商品列表和 feed；检查新内容出现。
3. 在 Netlify Functions 日志中搜索 `[storefront-cache] catalog refreshed`。此日志只在真正重新构建目录时输出，包含商品数、查询页数和缓存 JSON 字节数，不记录商品正文或客户信息。`jsonBytes` 用于比较响应大小，不是 Neon 实际计费流量。
4. 短时间重复读取未修改的目录时不应每次都出现刷新日志。如果每个请求都重建，检查部署环境的 Next Data Cache 支持，不能仅凭代码存在缓存函数就认定线上命中。
5. 对照 Neon 项目 Overview 的 Network transfer 增量；用量可能延迟约一小时。先观察一天，再按实际日均估算月用量，给后台编辑、平台抓取和增长留余量。不能在未观察实际流量前保证 5 GB 必然足够。

2026-10-25 已用生产构建和隔离的临时 SQLite 验证：15 次公开读取只构建一次目录；真实 Payload 设置保存后立即失效；测试商品上传图片、发布、首页图片与链接、匿名图片访问、feed 价格及下架后移除均通过。测试库仅从本地复制表结构，所有账号、图片与商品均为临时合成数据，未连接生产 Neon。Netlify 的缓存存储与实际月度用量仍须按上述步骤上线确认。

## 后续排查入口

开发环境使用 `DATABASE_URL_DEVELOPMENT`，Preview 使用 `DATABASE_URL_PREVIEW`，生产环境使用 `DATABASE_URL`。开发与 Preview 不应连接生产库；同一 Neon 项目内的不同分支仍属于同一个项目额度。没有开发数据库 URL 时，现有配置使用本地 SQLite。

已登录 Admin 的编辑 API、原生 Payload API、人工导入 / 清理及订单写入仍按各自权限直接访问数据库。它们不适合套公开缓存；如果部署后流量仍异常，应按 Netlify 请求路径、调用频率和缓存刷新次数定位，尤其关注直接请求 `/api/products`、`/api/media` 或频繁重建目录的来源。商品量大到整份目录不再适合内存筛选时，再改为查询索引与分页缓存。
