# Ginny Nana 电商上线检查清单

这份清单按当前 QuickCart 的 Next.js、Payload、Neon、Cloudflare R2、PayPal 架构整理。代码中已有的功能先标为“待端到端验收”；只有实际走完流程并检查线上配置后才改为“已验证”。

## P0：上线前必须验证

- [ ] 访客可以从商品列表进入详情，选中有效的 Length + Shape + Size 组合，并将正确 Variant 加入购物车。
- [ ] 禁用、缺货或不存在的 Variant 无法加入购物车；服务端重新核对价格、库存和商品发布状态，不信任浏览器提交值。
- [ ] 手机和桌面端均可完成购物车、地址填写、运费展示和 PayPal 结账；下单前明确展示总价及适用费用。
- [ ] PayPal 创建订单、批准、捕获、取消和失败路径均可正确结束；重复请求、重复 webhook 和网络重试不会重复扣款或创建重复订单。
- [ ] 订单状态与支付状态一致；支付成功后订单可查询，管理员可履约，并能处理取消、退款和部分退款。
- [ ] 支持的国家、地址格式、配送范围、运费及时效与商店政策一致；不支持的目的地会被明确阻止。
- [ ] 联系方式、隐私政策、服务条款、配送/退换政策可从结账和网站页脚找到，内容与实际运营一致。
- [ ] Payload 管理端和 Studio 均要求登录；顾客 API 不会返回供应商 SKU、采购链接或其他后台字段。
- [ ] Neon 和 R2 已确认备份及恢复方法；用备份演练恢复商品、订单和媒体引用。
- [ ] 生产环境错误有可查日志；关键支付、下单、媒体上传失败可以被发现并定位。

## P1：日常运营必须顺手

- [ ] 新商品默认 Draft；保存草稿不会公开，发布需要明确操作，编辑已发布商品可安全保存并继续发布。
- [ ] 商品 Variant 只由明确选择的 Length + Shape 配对与尺码生成；同步后保留匹配 Variant 的 SKU、价格、库存和图片。
- [ ] 首页 By Length / By Shape 只展示至少有一个启用 Variant 的维度值；筛选结果与商品详情的可购买 Variant 一致。
- [ ] 商品主图、图库和 Variant 图片可选用媒体库已有图片；失败上传和未关联图片按媒体清理规则处理，删除被引用媒体时有警告。
- [ ] 批量编辑支持搜索、分页、跨页选择和批量状态修改；保存失败会指出失败项，不丢失未保存编辑。
- [ ] 复制商品会生成新商品 ID 和 SKU，状态为 Draft；可复用商品资料，但不会继承库存或自动发布状态。
- [ ] 供应商 SKU 与采购 URL 仅后台可见，不进入 storefront、商品 JSON-LD、Google/Pinterest feed 或顾客 API。
- [ ] Google Merchant 与 Pinterest feed 的价格、库存、图片、链接、币种、国家和商品状态符合实际配置；商品变更后能及时更新。
- [ ] 管理员能快速找到低库存、缺图、无效 SKU、缺少价格及发布失败商品，并能修复后重试。
- [ ] 订单通知、顾客确认邮件、人工客服入口与发货流程有明确负责人和操作步骤。

## P2：持续优化

- [ ] 商品页包含准确的 title、description、canonical、结构化数据；站点地图和 robots 规则正确。
- [ ] 图片有合适尺寸、格式、替代文本和加载策略；主要页面在手机网络下仍可用。
- [ ] 关键页面可键盘操作，表单错误有清楚说明，文字与背景有足够对比度。
- [ ] 统计加购、开始结账、支付成功、退款等关键事件，并遵循适用的隐私与同意规则。
- [ ] 发布流程有可回滚的代码版本、环境变量清单和迁移检查步骤；定期检查依赖与安全更新。
- [ ] 定期复核转化率、支付失败、缺货取消、配送时长、退款原因和 feed 拒登原因。
